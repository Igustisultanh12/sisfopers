## Latar Belakang

Repo `kctrimatra` membutuhkan standar UI dan design system yang cukup tegas sebelum implementasi frontend berkembang lebih jauh. Tanpa keputusan ini, risiko drift visual, inkonsistensi bahasa UI, dan pencampuran makna warna sistem dengan warna domain akan meningkat sejak fase awal.

Karena repo masih berada pada tahap `bootstrap`, keputusan ini sengaja mengunci prinsip normatif yang stabil lebih dulu, sambil menahan detail implementasi yang memang lebih tepat lahir sebagai referensi teknis turunan.

## Scope

### Termasuk

- identitas visual global aplikasi
- batas pemakaian warna matra
- prinsip bahasa UI domain
- batas penggunaan lambang resmi dan pengganti visualnya
- struktur dasar token desain
- tipografi sans utama awal
- komponen UI inti fase awal
- posisi scope kartu anggota cetak

### Tidak Termasuk

- naming teknis final komponen atau struktur file frontend
- implementasi Blade, CSS, JavaScript, atau framework frontend tertentu
- aturan detail desain kartu anggota cetak
- kebutuhan warna Mabes atau gabungan yang belum punya kebutuhan operasional nyata

## Keputusan

1. Aplikasi `kctrimatra` wajib memakai satu identitas sistem hijau militer untuk seluruh chrome aplikasi.
2. Chrome aplikasi yang dimaksud minimal mencakup shell internal, guest/auth layout, sidebar, topbar, tombol primer, focus ring, link utama, dan navigasi global.
3. Warna matra tidak boleh menggantikan identitas sistem global.
4. Warna matra hanya boleh dipakai secara kontekstual pada elemen yang memang merepresentasikan identitas personel, satuan, atau dokumen tertentu.
5. Contoh elemen yang boleh memakai warna matra sejak fase awal:
   - badge matra
   - chip atau filter matra
   - edge kartu profil
   - avatar ring
   - kartu anggota
6. Contoh elemen yang tidak boleh memakai warna matra sebagai tema utama:
   - sidebar
   - topbar
   - tombol primer sistem
   - background halaman penuh
   - focus ring global
7. UI wajib memakai istilah operasional yang jelas dan baku, termasuk `matra`, `satuan`, `pangkat`, `NRP/NIP`, dan `status keanggotaan`.
8. Kode teknis mentah tidak boleh ditampilkan sebagai label UI operasional bila masih bisa diterjemahkan ke istilah yang jelas.
9. Pangkat tidak dipakai sebagai penanda matra di UI `kctrimatra`.
10. Identitas matra dibaca dari data verifikasi, surat keputusan, atau atribut domain lain yang memang menjadi sumber kebenaran matra.
11. UI tidak boleh mereproduksi lambang resmi kesatuan sebagai dekorasi aplikasi tanpa dasar otorisasi yang jelas.
12. Representasi visual matra di UI boleh memakai motif ikon atau simbol sederhana sebagai bahasa visual pengganti.
13. Struktur token desain resmi dibagi menjadi dua keluarga:
   - token sistem untuk brand, chrome, surface, tipografi, spacing, shadow, dan semantik umum
   - token matra untuk representasi identitas AD, AL, AU, dan kebutuhan lain yang kelak dibenarkan secara operasional
14. Status keanggotaan wajib dipisahkan secara visual dari badge matra.
15. Status keanggotaan memakai token semantik sistem, bukan token matra.
16. `IBM Plex Sans` ditetapkan sebagai font sans utama awal untuk UI `kctrimatra`.
17. Komponen UI inti fase awal yang wajib menjadi acuan implementasi adalah:
   - shell aplikasi internal dan guest/auth
   - page header
   - card
   - button dan processing button
   - input, select, dan textarea
   - table, pagination, dan empty state
   - alert, badge, dan loading overlay
   - badge matra
   - status badge
   - filter matra
18. Komponen seperti avatar ring, card edge, dan kartu anggota cetak boleh diposisikan sebagai fase lanjutan atau scope turunan.
19. Naming teknis seperti `x-ui.*` dan `x-matra.*` belum dibakukan sebagai kontrak final pada keputusan ini.
20. Kebutuhan cetak kartu anggota diakui sebagai scope yang sah, tetapi desain visual dan aturan cetaknya dibahas pada dokumen turunan terpisah saat scope cetak aktif.
21. Rincian token teknis dan katalog komponen teknis hidup sebagai referensi teknis turunan dari keputusan ini.
