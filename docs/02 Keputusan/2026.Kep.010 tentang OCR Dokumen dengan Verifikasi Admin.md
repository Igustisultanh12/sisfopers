## Latar Belakang
Diskusi `2026.07.03 Diskusi tentang OCR Dokumen dengan Verifikasi Admin` telah difinalkan (`[SELESAI]` di `00 Arsip`). OCR adalah fitur bantu, bukan otoritas. Keputusan ini mengunci scope OCR, model verifikasi, dan pemisahan OCR gambar vs structured import SK.

## Keputusan
1. **OCR = bantuan, bukan otoritas.** Semua hasil auto-match wajib verifikasi admin/koordinator (Kep.009 gating).
2. **Scope MVP:** KTP / KTA / Ijazah = OCR gambar (1-2 hlm, ringan, async). **SK massal = Structured Import (bukan OCR)** karena SK = PDF berlapis teks + struktur label/value.
3. **SK ribuan nama:** Structured Import + Queue bertahap (1 Job per PDF, per-halaman/chunk, parser posisional). TIDAK sinkron (hindari timeout). Idempotensi: dedupe by `nomor_surat` agar retry job tidak duplikat.
4. **Confidence score:** hanya untuk OCR gambar (KTP/KTA/Ijazah); cukup di referensi teknis. Tidak untuk SK teks.
5. **Cross-validation NIKC:** parser derive DOB & provinsi dari NIKC, cocokkan dengan teks SK; tidak cocok → flag review admin. Gender tidak di NIKC; derive dari `(W)` pangkat atau default Pria.
6. **Normalisasi nama:** strip prefix pangkat + suffix gelar sebelum match (reuse `display_pangkat` Kep.011). #11 T1/T5.
7. **Import SK → isi `riwayat_pendidikan`** (Kep.008) pakai kontrak parse "S2 Manajemen" → jenjang/program. Kolom Pendidikan SK → entri AKADEMIK.
8. **Repository:** hasil import simpan di Kep.007 (disk private, access log).
