## Tujuan

Dokumen ini memetakan komponen UI yang perlu tersedia untuk menerapkan keputusan UI aktif secara konsisten di fase awal pengembangan.

## Komponen Inti Fase Awal

### Shell dan struktur

- `layout` shell aplikasi internal
- `layout` guest atau auth
- `page-header`
- `card`

### Aksi dan feedback

- `button`
- `processing-button`
- `alert`
- `badge`
- `loading-overlay`
- `empty-state`

### Form dan data display

- `input`
- `select`
- `textarea`
- `table`
- `pagination`

### Komponen domain matra

- `matra-badge`
- `status-badge`
- `matra-filter`

## Aturan Komponen

- komponen umum memakai token sistem
- komponen matra membaca token matra hanya saat elemen itu memang menjadi penanda identitas domain
- `status-badge` wajib terpisah dari `matra-badge`
- pangkat tidak dijadikan logika visual untuk menentukan matra
- naming seperti `x-ui.*` dan `x-matra.*` masih bersifat arah awal, belum kontrak final

## Komponen Lanjutan

Komponen berikut belum wajib di fase awal, tetapi sah dipersiapkan sebagai turunan berikutnya:

- `avatar-ring`
- `card-edge`
- `id-card`

Komponen `id-card` perlu diskusi turunan tersendiri saat scope cetak aktif, karena kebutuhan visual cetak dan aturan outputnya berbeda dari UI kerja harian.

## Catatan Implementasi

- jika stack frontend yang dipilih nantinya berbasis Blade component, prefix seperti `x-ui.*` dan `x-matra.*` boleh dipakai
- jika stack frontend berubah ke pola lain, identitas komponennya boleh disesuaikan tanpa mengubah keputusan normatif
- jangan membuat komponen yang mengubah seluruh tema halaman mengikuti matra
