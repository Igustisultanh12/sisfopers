## Pemicu

User menetapkan bahwa verifikasi wajah tahap awal tetap penting sebagai bukti bahwa registrasi diajukan oleh personel yang bersangkutan, tetapi `face recognition` otomatis ditunda untuk dikaji lebih lanjut. Karena itu, rumah diskusi ini dipersempit khusus untuk `face recognition`, bukan lagi untuk seluruh verifikasi wajah awal.

## Temuan Awal

- repo sempat memiliki implementasi `face verification` yang mencampur dua hal berbeda: bukti wajah awal dan komparasi biometrik otomatis
- implementasi lama menyimpan sampel wajah lalu langsung menyalakan status lolos tanpa checkpoint yang matang
- tidak ada standar kemiripan, tidak ada fallback manual, dan tidak ada aturan retensi artefak biometrik yang final
- user kini memisahkan arah domain: `face verification` awal tetap dipertahankan sebagai kandidat modul registrasi, sedangkan `face recognition` otomatis dipindahkan ke diskusi khusus ini
- file controller, model, view, middleware, dan migration terkait wajah dikembalikan sebagai modul dorman, tetapi tetap tidak aktif di route produksi sambil menunggu diskusi registrasi difinalkan

## Opsi yang Dipertimbangkan

- aktifkan face recognition otomatis pada fase awal
- aktifkan hanya verifikasi wajah manual tanpa recognition otomatis
- tunda face recognition penuh sambil mempertahankan verifikasi wajah awal sebagai artefak registrasi

## Poin Diskusi

- apakah `face recognition` benar-benar dibutuhkan pada domain personel Komcad tahap ini
- jika dibutuhkan, untuk tujuan apa: anti-impersonasi login, validasi kehadiran, atau verifikasi lanjutan lain
- apakah sistem akan menyimpan embedding, template biometrik, atau hanya hasil evaluasi akhir
- siapa yang berwenang memverifikasi, membatalkan, atau mengulang hasil komparasi otomatis
- bagaimana standar kemiripan, false positive, false negative, dan fallback manual ditetapkan
- bagaimana retensi, penghapusan, audit, dan perlindungan data biometrik dijalankan

## Hasil Diskusi

- `face recognition` otomatis ditunda penuh
- verifikasi wajah awal sebagai bukti registrasi tidak dibahas sebagai scope dokumen ini dan diarahkan ke diskusi akun/registrasi
- tidak ada gate operasional berbasis `face recognition` yang boleh hidup sebelum keputusan turunan lahir

## Checklist Pra-Finalisasi

- [ ] tujuan bisnis `face recognition` disepakati
- [ ] bentuk data biometrik yang boleh disimpan disepakati
- [ ] standar kemiripan dan fallback manual ditulis jelas
- [ ] aturan privasi, retensi, audit, dan penghapusan data disepakati
- [ ] keputusan turunan khusus lahir sebelum route atau gate recognition diaktifkan

## Catatan untuk AI Agent

- jangan hidupkan komparasi wajah otomatis, kalkulasi embedding, atau gate `face recognition` sebelum diskusi ini dinaikkan menjadi keputusan turunan
- bedakan selalu `face verification` awal sebagai bukti registrasi dari `face recognition` otomatis sebagai evaluasi biometrik
- jika ada eksperimen teknis baru, catat dulu opsi dan risikonya di dokumen ini, jangan langsung hidupkan di runtime aktif

## Pertanyaan Terbuka

- apakah kebutuhan awal sebenarnya cukup dengan verifikasi wajah manual atau sampel bukti registrasi tanpa recognition otomatis
- apakah ada dasar kebijakan internal yang memperbolehkan penyimpanan dan pemrosesan embedding wajah personel
- apakah `face recognition` nantinya diposisikan sebagai syarat login, syarat presensi, atau hanya alat bantu admin

## Rencana Tindak Lanjut

- biarkan status dokumen ini `Deferred` sampai user membuka kembali topik `face recognition`
- gunakan dokumen ini sebagai satu-satunya rumah diskusi aktif untuk komparasi wajah otomatis dan embedding biometrik
- bila topik dibuka lagi, lanjutkan dari pemisahan domain yang sudah ditetapkan: verifikasi wajah awal di diskusi akun, `face recognition` di diskusi ini
