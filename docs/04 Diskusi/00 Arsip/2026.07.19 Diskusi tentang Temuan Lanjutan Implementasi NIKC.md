## Pemicu

Setelah diskusi `2026.07.16` menetapkan daftar drift utama, terjadi temuan tambahan dari inspeksi UI dan validasi form:

- Form `Register.vue` mengizinkan input NIKC sebanyak 16 digit atau 18 digit.
- Tidak ada validasi panjang eksplisit 17 digit serta constraint numerik di sisi UI sebelum dikirim ke backend.
- Tidak ada warning khusus ketika pengguna memasukkan 16 digit yang kurang dari standar 17 digit.
- Label login di UI menampilkan "Username / NIKC", seharusnya hanya "NIKC" untuk publik; username hanya untuk superadmin internal.

Ini menimbulkan risiko NIKC non-standard masuk ke sistem meskipun Kep.003 sudah mengunci format 17 digit sebagai norma final.

## Tujuan

- Mencetak temuan tambahan drift terkait validasi panjang dan tipe karakter NIKC.
- Menjadi basis untuk menambahkan aturan input NIKC yang lebih ketat di form publik dan admin.
- Menjadi referensi sinkronisasi ulang antara Kep.003 dan seluruh lapisan input.
- Menyelaraskan label login publik agar hanya menampilkan "NIKC" secara default.

## Temuan Tambahan

### 11. Validasi panjang NIKC belum di-enforce — DRIFT

- Form registrasi (`resources/js/Pages/Auth/Register.vue`) tidak membatasi panjang input NIKC.
- Server-side (`AuthController::register`) menggunakan `required|string|max:255`.
- Akibat: pengguna bisa menginput 16 digit atau 18 digit, yang tidak sesuai dengan format 17 digit yang diatur dalam Kep.003 Klausul 3.

### 12. Tidak ada validasi numerik eksplisit — DRIFT

- Form dan controller tidak memastikan bahwa NIKC hanya berisi angka.
- Kep.003 Klausul 4 menegaskan: "hanya angka".

### 13. Tidak ada warning khusus untuk 16 digit — KEBUTUHAN

- Pengguna yang menginput 16 digit (kurang 1 digit) tidak mendapat indikasi visual bahwa NIKC harus 17 digit.
- Kep.003 mengharuskan panjang tepat 17 digit.

### 14. Label login publik masih menampilkan "Username / NIKC" — DRIFT UI

- `resources/js/Pages/Auth/Login.vue` menampilkan label "Username / NIKC" dan placeholder "Masukkan username atau NIKC".
- Untuk publik login, yang valid adalah NIKC personel. Username adalah identifier internal yang hanya digunakan oleh superadmin.
- Kep.009 meng identifier login sebagai `NIKC atau username`, namun untuk antarmuka publik, NIKC harus menjadi satu-satunya opsi yang ditampilkan.

### 15. Admin tetap boleh input NIKC melalui form admin — SESUAI

- Form admin (`Admin/Personel/Create.vue`, `Admin/Personel/Edit.vue`) mengizinkan input NIKC bebas.
- Ini tidak termasuk drift karena admin memang perlu fleksibilitas untuk mencatat NIKC manual.
- Namun validasi 17 digit tetap perlu diterapkan di form admin untuk menjaga konsistensi data.

## Dampak

1. Data NIKC di database bisa bercampur format: teks 16, 17, 18 digit, atau string `KC-...`.
2. Validasi kepatuhan terhadap Kep.003 tidak lengkap; audit mendokumentasikan norma tapi runtime belum menegakkan.
3. Pengguna akhir tidak mendapat feedback awal tentang kelengkapan digit NIKC.
4. Antarmuka login membingungkan publik karena menampilkan dua jenis identifier sekaligus.

## Saran penanganan singkat

- Tambahkan validasi `digits:17|numeric` pada seluruh request yang menerima NIKC: registrasi, admin store/update, SkepPublicController, dan SkepRequest.
- Tambahkan validasi front-end di `Register.vue` agar input NIKC:
  - hanya menerima angka,
  - dibatasi 17 digit,
  - menampilkan warning ketika panjang < 17 atau > 17.
- Ubah label login publik menjadi "NIKC" saja (tanpa "Username / ..."), karena publik seharusnya hanya menggunakan NIKC.
- Admin tetap dapat menggunakan username untuk login internal, namun label UI publik hanya menampilkan NIKC.
- Normalisasi label "login menggunakan NIK" menjadi "login menggunakan NIKC atau username" di notifikasi.
- Lanjutkan temuan drift utama yang sudah tercatat dalam diskusi 2026.07.16.

## Pertanyaan Terbuka

- Apakah untuk sementara menolak input NIKC non-17 digit sepenuhnya, atau masih menerima dengan warning?
- Apakah perlu membuat workplan terpisah untuk menutup seluruh drift terkait NIKC?
- Apakah label login publik harus mengarahkan pengguna ke NIKC saja, atau tetap menyebutkan username untuk kasus khusus?
